# Argus two week owner pilot

Owner: Edward. Participation accepted November 18, 2026. Results are pending real
use; implementation checks and model judgments are not pilot outcomes.

The question is whether Argus repeatedly changes what you need to research and
shows enough evidence to justify that change. Choose five companies and two
themes you already follow. Use your normal workflow as the comparison.

## Day 1

Record the coverage list, your current research questions, and the time actually
spent answering one question with your usual sources. Save the initial research
view in Argus. Set the start date when you begin, not from this document's date.

## Days 2 through 14

Spend about ten minutes per visit reviewing your followed subjects and Saved
checkpoints. Record visits you choose to make yourself separately from prompted
test visits. For each useful change, save the event link, the supporting article,
what changed in your research, and the next question. Verify a source before
treating an implication as established. Record misleading or missing results too.

Keep actual minutes separate from estimates. A faster session is useful only if
it answers a comparable question. Investment returns are not an outcome of this
short pilot. Do not post private research logs to the public code repository.

Suggested private log columns:

| Date | Voluntary or prompted | Question | Argus minutes | Comparison minutes, if measured | Useful change and evidence link | False alarm or missing information | Next action |
|---|---|---|---|---|---|---|---|
| | | | | | | | |

## Days 7 and 14

Review which findings changed your research, which required correction, and which
tasks still forced you elsewhere. Identify whether Saved preserved useful context
between visits. Count observed visits and verified discoveries; leave unknowns
blank. One person's pilot informs this product direction, not market-wide demand.

Provisional expansion gate: at least eight voluntary visits, three distinct
verified findings that changed research, and a repeatable task completed with
less effort than your prior workflow. Any material unsupported implication needs
a traced correction before calling the trust problem closed. These are proposed
decision criteria, not achieved results or mandatory usage targets.

At the end, decide whether to continue using Argus without a reminder, what you
would miss if it disappeared, and the single improvement that would most help.
Recruiting others or upgrading services requires a separate explicit action.

## Accuracy review

Use small source-grounded batches. Keep A/direct, B/contextual, C/irrelevant and
D/insufficient-evidence decisions separate from model suggestions. Preserve
reviewer, date, scope and rationale. Existing TM1b examples and any examples used
to adjust the matcher are development data. A future holdout must use new event
groups after the implementation is frozen, with predictions frozen before your
judgments; it must not become training data for the same claimed evaluation.
